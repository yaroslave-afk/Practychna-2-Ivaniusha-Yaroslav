> Бланк заповнюють, не змінюючи структури розділів. Порожні заготовки блоків коду замінюють власними виводами. Позначки-підказки в кутових дужках вилучають.

## Частина A. Збір експериментальних даних

### Завдання A.1. Формування запиту вручну

**Команда:**

```
PS C:\WINDOWS\system32> $d = "netbsd.org"
PS C:\WINDOWS\system32> $c = New-Object System.Net.Sockets.TcpClient($d, 80)
PS C:\WINDOWS\system32> $s = $c.GetStream()
PS C:\WINDOWS\system32> $w = New-Object System.IO.StreamWriter($s)
PS C:\WINDOWS\system32> $w.Write("GET / HTTP/1.1`r`nHost: $d`r`nConnection: close`r`n`r`n")
PS C:\WINDOWS\system32> $w.Flush()
PS C:\WINDOWS\system32> (New-Object System.IO.StreamReader($s)).ReadToEnd()
```

**Набраний запит:**

```
$w.Write("GET / HTTP/1.1`r`nHost: $d`r`nConnection: close`r`n`r`n")
```

## Частина B. Розбір полів заголовка

Розбирається відповідь, отримана в завданні A.1.

**Загальна кількість полів заголовка у відповіді:**

| № | Поле заголовка | Значення | Призначення (власне формулювання) | Походження: сервер / проміжний вузол / не визначено | Обґрунтування |
|---|---|---|---|---|---|
| 1 |Date |Mon, 05 Oct 2026 14:21:18 GMT |Вказує дату та час формування відповіді сервером. |сервер |Поле містить час формування HTTP-відповіді та є стандартним полем відповіді сервера |
| 2 |Server |Apache/2.4.62 (Unix) |Повідомляє інформацію про програмне забезпечення веб-сервера, який обробив запит. |сервер |Значення безпосередньо вказує на Apache/2.4.62, тому поле характеризує сервер, що сформував відповідь. ||
| 3 |Last-Modified | Sat, 26 Sep 2026 13:30:04 GMT|Вказує час останньої зміни запитаного ресурсу. |сервер |Час зміни ресурсу може бути відомий саме серверу, який зберігає та обслуговує цей ресурс. |
| 4 | ETag|3160-65c62d4a07823 |Ідентифікатор конкретної версії ресурсу, який може використовуватися для перевірки актуальності кешованої копії. |сервер |Значення пов'язане з конкретним представленим ресурсом і сформоване сервером. |
| 5 |Accept-Ranges | bbytes|Повідомляє, що сервер підтримує отримання ресурсу частинами за діапазонами байтів. |сервер |Поле описує можливості сервера щодо обробки запитів діапазонів |
| 6 |Content-Length |12640 |Вказує розмір тіла HTTP-відповіді в байтах. |сервер |Значення відповідає фактичному розміру отриманого HTML-документа.|
| 7 |X-Frame-Options | SAMEORIGIN|Обмежує використання сторінки всередині фрейму сторінками з іншого джерела. |сервер |Поле має характер налаштування безпеки веб-сервера та присутнє у відповіді самого ресурсу. |
| 8 |X-Xss-Protection |1; mode=block |Вказує налаштування поведінки механізму захисту браузера від XSS-атак. |сервер |Поле є налаштуванням безпеки HTTP-відповіді; ознак його додавання проміжним вузлом немає. |

> Рядок наводять на кожне поле, яке реально надійшло. Зайві рядки вилучають, за потреби додають нові. Поле, походження якого встановити не вдалося, зазначають із позначкою «не визначено» та поясненням утруднення.

## Частина D. Висновки

спочатку я вручну відправляв запити до netbsd.org і дивився що повертає сервер в a1 сервер повернув 200 ok і html сторінку коли в a2 я убрав заголовок host сервер вже повернув 400 bad request це показало що для http 11 цей заголовок є обовязковим я перевірив що буде якщо змінити host в a3.1 і a3.2 навіть з іншим або неіснуючим значенням сервер все одно повернув 200 ok і ту саму сторінку а в a3.3 при використанні http 10 без host помилки не було мені було трохи дивно що результат майже не змінився при різних значеннях host в a4 я відправив два запити через одне зєднання на перший запит сервер повернув 404 not found а на другий 200 ok це показало що через одне зєднання можна відправити декілька запитів в a5 я використав curl і побачив що програма сама додає заголовки user-agent та accept в a6 я зробив такий самий запит через захищене https зєднання і отримав 200 ok найважче було зрозуміти які заголовки добавляє сам сервер а які могли добавлятись проміжними вузлами тому по одному виводу це точно визначити не завжлди можна

**D.1.** Що з поведінки сервера виявилося неочевидним або несподіваним. Конкретно, з посиланням на рядок виводу.

для мене було дивно що при зміні Host на kpi.ua сервер все одно повернув свою сторінку і 200 OK вивід починається з рядка HTTP/1.1 200 OK також навіть з неіснуючим Host sybau.invalid сервер повернув таку саму сторінку

**D.2.** Яке з полів заголовка викликало найбільше утруднення при визначенні походження (частина B) та з якої причини.


**D.3.** Яке питання залишилося без відповіді після виконання роботи.

залишилося питання чи є між моїм компютером і сервером netbsd.org якісь хаби і чи вони змінюють або додають заголовки HTTP це по отриманих відповідях точно визначити не вийшло

## Контрольні питання

**1.** У завданні A.1 сервер не надсилав відповіді, доки не було введено порожній рядок. Чим це зумовлено?

сервер чекав на завершення заголовків HTTP запиту порожній рядок означає закінчення заголовків тобто після нього сервер вже розуміє що запит можна обробляти

**2.** Порівняйте результати завдань A.1, A.2 та A.3.1–A.3.3 (таблиця Додатка Д). За яких значень поля `Host` і за якої версії протоколу сервер обслуговує запит, а за яких — ні? Яку задачу розв'язує поле `Host`? Відповідь має посилатися на конкретні рядки ваших виводів.

в A1 був Host: netbsd.org і HTTP/1.1 сервер повернув 200 OK в A2 заголовка Host взагалі не було і сервер повернув 400 Bad Request в A31 з Host: kpi.ua сервер знову повернув 200 OK а в A32 з Host sybau.invalid також був 200 OK в A33 використовувався HTTP/1.0 без Host і сервер теж повернув 200 OK

**3.** Скільки відповідей надійшло у завданні A.4 і з якими кодами стану? Чи залежить відповідь сервера на порту 80 від запитаного шляху — і що це говорить про роль цього сервера? Якщо надійшла одна відповідь, знайдіть у ній поле заголовка, яке це пояснює, або зазначте, що такого поля немає. Якщо надійшло дві — що це означає для клієнтської програми, яка завантажує сторінку з великою кількістю вкладених ресурсів?

в A4 надійшло дві відповіді перша була 404 Not Found для неіснуючого шляху /opism-pr02-12345 друга була 200 OK для шляху / це показує що відповідь сервера залежить від запитаного шляху тобто сервер не просто приймає всі запити однаково а перевіряє який ресурс запросили

**4.** Які поля заголовка програма `curl` додала самостійно (завдання A.5)? Ці поля не є обов'язковими — сервер відповів і без них у завданні A.1. З якою метою їх додано?
